# RNA-Seq Analysis Pipeline using Snakemake

## Overview

This is a Snakemake-based pipeline designed for comprehensive RNA-Seq data analysis. It automates the process from raw sequencing reads (FASTQ) to differential gene expression analysis and Transcripts Per Million (TPM) quantification. The pipeline includes steps for reference genome preparation, read quality control, mapping, feature counting, and differential expression.

Key features:
- Automated reference genome downloading and STAR index generation.
- FASTQ file downloading from SRA (optional, if SRA accessions are provided).
- Adapter and quality trimming of reads using Trim Galore.
- Read alignment to the reference genome using STAR.
- Gene-level read counting using featureCounts.
- Differential gene expression analysis (example with DESeq2 via an R script).
- TPM calculation.
- Conda integration for managing software dependencies.
- Comprehensive configuration via a central `config.json` file.

## Requirements

To run this pipeline, you will need:

1.  **Miniconda (or Anaconda)**: To manage software dependencies and create isolated environments.
    *   Installation instructions: [Miniconda](https://docs.conda.io/en/latest/miniconda.html)
2.  **Git**: To clone this repository.
    *   Installation instructions: [Git](https://git-scm.com/book/en/v2/Getting-Started-Installing-Git)

## Setup

1.  **Clone the Repository**:
    Open your terminal and clone this repository to your local machine:
    ```bash
    git clone <repository_url> # Replace <repository_url> with the actual URL
    cd <repository_directory_name> # Replace <repository_directory_name>
    ```

2.  **Create and Activate Conda Environment**:
    The pipeline uses Conda to manage all its software dependencies. The required environment is defined in the `env/rnaseq.yml` file.
    Create the environment using the following command:
    ```bash
    conda env create --file env/rnaseq.yml
    ```
    This command will create a new Conda environment named `rnaseq` (or as specified within the YAML file, usually the filename). After the environment is created, activate it:
    ```bash
    conda activate rnaseq
    ```
    You will need to activate this environment every time you want to run the pipeline in a new terminal session.

## Configuration (`config.json`)

The pipeline's behavior is primarily controlled by the `config.json` file. Below is a description of its main sections and parameters:

```json
{
  "rundeg-output": "rundeg_featureCount", // Directory name (within the main output_dir) for differential expression results
  "general": {
    "threads": 16,                       // Maximum number of threads the pipeline can use
    "samples_tsv_path": "samples.tsv",   // Path to the TSV file listing your samples
    "output_dir": "output"               // Main directory where all pipeline outputs will be stored
  },
  "paths": {
    "reference_genome_dir": "reference", // Directory to store/find the STAR genome index
    "gtf_file": "reference/TAIR10_prepared.gtf", // Path to the GTF annotation file; this is generated by the prepare_reference rule
    "tools_dir": "src",                  // Directory containing auxiliary scripts
    "scripts": {                         // Names of the scripts within tools_dir
        "fix_featCnt_header": "fix_featCnt_header.py", // Script to fix featureCounts output header
        "tpm_calculator": "tpm_raw_exp_calculator.py", // Script to calculate TPM
        "run_DE_analysis": "run_DE_analysis.pl",    // Script for running differential expression analysis
        "analyze_diff_expr": "analyze_diff_expr.pl" // Script for further analysis of DE results
    }
  },
  "reference_preparation": { // Parameters for the reference genome preparation step
    "base_dir": "reference_sources", // Directory to download raw FASTA/GFF files
    "fasta_url": "https://www.arabidopsis.org/download_files/Genes/TAIR10_genome_release/TAIR10_chromosome_files/TAIR10_chr_all.fas", // URL for raw FASTA
    "gff_url": "https://www.arabidopsis.org/download_files/Genes/TAIR10_genome_release/TAIR10_gff3/TAIR10_GFF3_genes.gff",          // URL for raw GFF3
    "raw_fasta_name": "TAIR10_chr_all.fas",     // Filename for downloaded FASTA
    "fixed_fasta_name": "TAIR10_chr_all.fas.fixed", // Filename for FASTA after header fixing
    "raw_gff_name": "TAIR10_GFF3_genes.gff",      // Filename for downloaded GFF
    "star_genome_load": "LoadAndKeep",        // STAR --genomeLoad option
    "star_sjdb_overhang": 99,                 // STAR --sjdbOverhang option
    "star_genome_sa_index_nbases": 10         // STAR --genomeSAindexNbases option
  },
  "params": { // Tool-specific parameters
    "fastqdump": {}, // Parameters for fastq-dump (if used)
    "trimming": {    // Parameters for Trim Galore
      "three_prime_clip_R1": 10,
      "three_prime_clip_R2": 10,
      "max_n": 50
    },
    "mapping_star": { // Parameters for STAR alignment
      "outFilterMultimapNmax": 10,
      "alignIntronMin": 30,
      "alignIntronMax": 55000
    },
    "readscount_featureCounts": { // Parameters for featureCounts
      "quality_threshold": 10,
      "strandedness": 0 // 0: unstranded, 1: stranded, 2: reversely stranded
    },
    "rundeg": { // Parameters for the differential expression (DE) script (run_DE_analysis.pl)
      "method": "DESeq2",
      "samples_file": "samplefile",     // Path to the sample metadata file for DE analysis (see below)
      "contrasts_file": "contrasts"     // Path to the contrasts file for DE analysis (see below)
    },
    "diffexpr": { // Parameters for the DE results analysis script (analyze_diff_expr.pl)
      "p_value_threshold": "1e-3",
      "fold_change_threshold": 1,
      "max_genes_clust": 40000
    }
  }
}
```

### `samples.tsv` File

The `general.samples_tsv_path` in `config.json` points to a tab-separated values (TSV) file that lists the samples to be processed. It should have at least one column named `sample`. If you are using SRA accession numbers that `fastq-dump` can process directly, these would go into the `sample` column.

Example `samples.tsv`:
```tsv
sample
SRR000001
SRR000002
SRR000003
```
If your FASTQ files are already downloaded, this file will still be used to get the list of sample names for creating directory structures and naming outputs. The `fastqdump` rule would be skipped if its output files already exist.

### `samplefile` and `contrasts` for Differential Expression

The `rundeg` rule uses two additional files, specified by `config.params.rundeg.samples_file` and `config.params.rundeg.contrasts_file`. These files are typically user-provided and define how samples are grouped and which comparisons to make for differential expression analysis.

*   **`samplefile`**: A tab-separated file mapping sample names (as in `samples.tsv`) to conditions or groups.
    Example:
    ```tsv
    sample	condition
    SRR000001	control
    SRR000002	treatment
    SRR000003	control
    ```
*   **`contrasts`**: A tab-separated file defining the contrasts (comparisons) to be made between conditions.
    Example (comparing 'treatment' vs 'control'):
    ```tsv
    treatment	control
    ```

## Running the Pipeline

Once the setup and configuration are complete, you can run the pipeline using Snakemake.

1.  **Activate the Conda Environment** (if not already active):
    ```bash
    conda activate rnaseq
    ```

2.  **Execute Snakemake**:
    The most common command to run the pipeline is:
    ```bash
    snakemake --use-conda --cores <N>
    ```
    *   `--use-conda`: This flag tells Snakemake to use the Conda environments specified in the Snakefile (via the `conda:` directive in each rule). It will automatically create or use the environment defined in `env/rnaseq.yml`.
    *   `--cores <N>`: Specifies the maximum number of CPU cores Snakemake can use. Replace `<N>` with an appropriate number for your system (e.g., `--cores 8`).

3.  **Dry Run**:
    To see what tasks Snakemake would execute without actually running them, perform a dry run:
    ```bash
    snakemake --use-conda -n
    ```
    This is useful for checking the workflow and dependencies.

4.  **Generate Workflow DAG (Directed Acyclic Graph)**:
    To visualize the workflow, you can generate a DAG image:
    ```bash
    snakemake --dag | dot -Tpng > dag.png
    ```
    This requires `graphviz` to be installed (which should be part of the Conda environment or can be installed separately).

5.  **Unlock Directory (if needed)**:
    If a previous Snakemake run was interrupted, the working directory might be locked. You can unlock it with:
    ```bash
    snakemake --unlock
    ```

## Output Structure

All outputs are stored in the directory specified by `config.general.output_dir` (default: `output/`). The main subdirectories include:

*   `reference_sources/`: Contains downloaded raw FASTA and GFF files, and the processed (header-fixed) FASTA.
*   `reference/`: Contains the prepared GTF file and the STAR genome index.
*   `output/<sample_name>/RAW/`: Raw FASTQ files (if downloaded by `fastqdump`).
*   `output/<sample_name>/TRIM/`: Trimmed FASTQ files from Trim Galore.
*   `output/<sample_name>/`: Contains alignment outputs (BAM files, logs) for each sample from STAR.
*   `output/featureCount.cnt`: Raw gene counts from featureCounts.
*   `output/featureCount.cnt.fixed`: Gene counts with a fixed header.
*   `output/featureCount.cnt_for_tpm`: Intermediate file for TPM calculation.
*   `output/featureCount.cnt_for_tpm.tpm.tab`: Final TPM values per gene.
*   `output/<config.rundeg-output>/`: Directory containing results from the differential expression analysis (e.g., from `run_DE_analysis.pl`).
*   `output/Final_analysis/`: Contains matrices and other summary files from `analyze_diff_expr.pl`.
*   `output/logs/`: Contains log files for each rule and sample, which are crucial for troubleshooting.

## Troubleshooting

*   **Log Files**: The primary resource for troubleshooting is the log files located in `output/logs/`. Each rule execution for each sample/step typically generates a log file. Check these files for specific error messages.
*   **Conda Environment Issues**: Ensure the Conda environment (`env/rnaseq.yml`) was created successfully and is activated (`conda activate rnaseq`). If you encounter "command not found" errors, it's often an environment issue.
*   **File Paths**: Double-check all paths in `config.json`, especially `samples_tsv_path`, and paths to user-provided files like `samplefile` and `contrasts` for the `rundeg` step.
*   **Resource Limits**: Some steps, like STAR alignment, can be memory-intensive. Ensure your system has adequate resources.
*   **Interrupted Runs**: If the pipeline is interrupted, use `snakemake --unlock` before re-running. Snakemake is generally good at resuming from where it left off.
